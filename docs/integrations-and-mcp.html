What MCP does

MCP is a standard way for an AI app to discover and call tools offered by another service.

Your app is the host

The API connects to MCP servers and gives the agent a selected set of tools for a run.

An MCP server offers tools

A server might offer actions such as searching documentation, looking up email threads, or listing classes.

The agent chooses a tool

The model can request an enabled tool when it helps answer the user. Your server sends the request and returns the result.

You control the connection

You connect an integration, attach it to an agent, and set which discovered tools are enabled and need approval.

Think of MCP like a common plug. Each service still decides what its server can do and what access its account grants. MCP standardizes how your app discovers and calls those capabilities.

Integrations already in your app

Your app has a remote MCP marketplace. It supports vendor-hosted Streamable HTTP servers and has two connection styles: direct connections and Composio-managed connections. The seeded catalog includes Context7 and Exa; the available list is controlled by the app’s Integrations catalog.

Connection typeWhat it meansCredential handling
Direct remoteYour API connects to the vendor MCP endpoint. A listing can require no login, an API key, or OAuth.OAuth tokens and API keys are encrypted and used on the server.
Composio-managedComposio creates a per-user MCP session for a connected provider. Your API calls that session.Session details and headers are stored encrypted server-side.
Local stdioA process running on the same machine communicates over standard input/output.Not the marketplace flow in your deployed app; it needs a long-lived host to run that process.

The app discovers tools from the server and caches their names, descriptions, and input schemas. You can then choose tools per agent. A server being connected does not automatically mean every agent can use every tool.

How to connect and use an integration

In the mobile app, open Integrations (the MCP marketplace), choose a listing, and follow its connection instructions.

Choose a listingBrowse the marketplace and open the integration details.
Connect your accountUse Connect, enter a key, or finish the OAuth login in the browser.
Attach it to an agentSelect the agent that should have access to the integration.
Choose toolsEnable only the tools you want. Set approval for actions that change or send things.

Once attached, use that agent in chat or a task. The agent can call its enabled integration tools during the run. On the integration detail screen you can refresh its tool list, change per-tool settings, or disconnect it. Disconnecting removes its tools from agents.

Example: connect Context7, attach it to your coding agent, and enable its documentation lookup tools. Ask the agent about a library; it can query the live docs instead of relying only on model memory.

What happens behind the scenes

  1. The mobile app calls your authenticated API to connect to the selected catalog listing.
  2. The API validates the remote endpoint, completes the appropriate authentication flow, and stores credentials encrypted.
  3. The API talks MCP to the remote server and discovers its tools. Tool definitions are cached in the database.
  4. You attach selected tools to an agent. The server keeps a per-agent allow-list and approval settings.
  5. At run time, the API loads only tools allowed for that agent, calls the remote MCP server when needed, and returns a bounded, redacted result to the agent.

Provider/service secrets are kept in the API environment. The mobile app stores the Supabase session, not provider credentials. The API also checks remote URLs to reduce server-side request forgery risk and enforces the user identity on protected routes.

Adding Gmail and Google Classroom

Google publishes remote MCP servers for both products. They can fit your app’s direct remote MCP pattern, but they are currently in the Google Workspace Developer Preview.

ServiceOfficial MCP endpointExamplesStatus
Gmailhttps://gmailmcp.googleapis.com/mcp/v1Search threads, read messages, create drafts, manage labelsDeveloper Preview
Classroomhttps://classroommcp.googleapis.com/mcp/v1List courses, view coursework, create announcements or courseworkDeveloper Preview

What you need to do

  1. Join the Google Workspace Developer Preview and choose a Google Cloud project.
  2. Enable the Gmail API and Gmail MCP service; enable the Classroom API and Classroom MCP service.
  3. Configure Google Auth Platform and create a Web application OAuth client. Google requires Workspace MCP OAuth clients to have Use this client for an AI-powered agent selected.
  4. Register your app’s callback URL with Google. Configure the scopes needed for your intended tools and request offline access so the connection can refresh tokens.
  5. Update your app’s OAuth adapter to use Google’s client ID and secret and the chosen scopes. Then add Gmail and Classroom as OAuth marketplace listings and connect them through the app.

Implementation note: the app already has OAuth, PKCE/state handling, encrypted credential storage, and a remote MCP client. Its current OAuth flow is based on dynamic client registration and a public client. Google’s Workspace MCP setup requires a configured OAuth client ID/secret, so the generic flow needs a Google-compatible option before these listings can be expected to connect. Don’t treat adding the two endpoint URLs alone as a complete integration.

Start with narrow permissions

For Gmail, decide whether the agent only needs to find and read messages or also create drafts and change labels. Google documents scopes including gmail.readonly, gmail.compose, and gmail.modify; the last grants broader access. Gmail’s current MCP tool list includes draft creation but not sending mail.

For Classroom, choose scopes based on whether you need course listing, coursework, announcements, or student submissions. The permissions available can depend on whether the signed-in user is a teacher or student and their access to each class.

After connection, use the same app flow: attach each integration to an agent, enable only selected tools, and keep tools that publish or modify coursework behind approval.

Permissions and safety

  • Use least privilege: request the smallest Google scopes and enable only the MCP tools an agent needs.
  • Require approval for side effects: draft, publish, label, send, delete, or update actions should have deliberate approval settings. High-risk tools cannot have approval disabled by the API.
  • Review before acting: keep a human review step before messages or classroom updates are published.
  • Treat tool output as untrusted: email bodies, assignment text, tool descriptions, and documents can contain misleading instructions. They must not change an agent’s tool permissions.
  • Disconnect when no longer needed: revoke access in Google as well if you want to invalidate the OAuth grant at the source.
In one sentence: MCP provides the connection standard; Google provides the Gmail/Classroom capabilities and OAuth permissions; your app decides which agent can use each tool and when you must approve an action.
