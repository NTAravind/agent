MASTER_SPEC.md

Master Spec: Personal AI Agent ("Grok-style" assistant + Second Brain)

Status: v0.1 draft · Owner: you (single user) · Last updated: 12 Nov 2026

1. Vision

A personal, always-available AI assistant you can use from your phone (Expo) and web. It chats, researches, runs long tasks in the background, remembers you through an Obsidian-style second brain, can be extended with MCP servers in one click, and can show answers as live dashboards ("canvas").

2. Goals

  • G1. One agent that plans and executes tasks from a single instruction, asking approval before sensitive actions.
  • G2. A second brain: your Obsidian vault (markdown + [[wikilinks]]) is searchable and writable by the agent.
  • G3. MCP store: add/remove tool servers per agent with one tap.
  • G4. Canvas: agent renders dashboards/reports natively in the app from a JSON spec.
  • G5. Runs anywhere (cloud), free, single user.
  • G6. Provider-agnostic: Google, Groq and OpenRouter selectable per chat/agent via the AI SDK, with automatic fallback.

3. Non-goals (v1)

  • Multi-user, teams, billing, public sharing.
  • Self-hosted model inference.
  • stdio MCP servers (needs a long-lived host).
  • X/Twitter intelligence (paid API) and realtime speech-to-speech (not free).
  • Video generation (not on Gemini free tier).

4. Constraints

Constraint Consequence
Free tiers only Gemini free tier, Vercel Hobby, Supabase Free, Inngest Hobby. Design for quotas.
Personal use Vercel Hobby (non-commercial) is acceptable. Auth = your GitHub account only.
Mobile-first Expo app is the primary client; the server is a Next.js API.
Privacy Gemini free tier may use requests to improve Google products. Don't send sensitive notes through it by default.

5. Principles

  1. Server owns intelligence, client owns pixels. Keys and agents live on the server; Expo renders.
  2. Durable by default. Anything over ~1 minute runs in Inngest, never inside a chat request.
  3. Approve before harm. Sensitive tools require explicit approval.
  4. Specs, not code. The agent emits validated JSON for UI; never executable code.
  5. Rebuildable. Supabase is an index; the GitHub vault is the source of truth for notes.

7. Success criteria

  • Ask from phone → get streamed answer with citations in < 3 s to first token.
  • "Research X and put it on a dashboard" completes in the background and appears in the Canvas tab.
  • Agent finds a note you wrote months ago and links it in its answer.
  • Adding an MCP server takes ≤ 3 taps and its tools work in the next run.
  • Monthly cost: $0.

8. Glossary

Agent: configured LLM + tools + instructions. Run: one execution of an agent graph. Vault: Obsidian folder in a private GitHub repo. Canvas: persisted JSON UI spec rendered natively. MCP: Model Context Protocol tool server.

5. Known constraints

  • Remote (streamable HTTP) MCP only. stdio needs a long-lived worker.
  • Inngest quota is consumed per step: batch work, keep short chats off Inngest.
  • Supabase pause: add a GitHub Actions cron ping (free, not counted against Inngest).
  • Handle 429s with backoff, then fall back across Google → Groq → OpenRouter (order configurable). Skip fallbacks that lack a required capability.
  • Embeddings use one fixed model; don't switch it with the chat model.
  • Streaming on device can be flaky; keep an XHR-based transport as fallback.
ARCHITECTURE.md

Architecture

1. Overview

 Expo app ──HTTPS (JWT)──► Next.js on Vercel ──► AI SDK ──► Gemini
   │  ▲                       │   │   │
   │  │ stream/poll           │   │   └─► LangGraph graphs ──► tools / MCP servers
   │  └───────────────────────┘   │
   │                              ├─► Inngest (durable runs, cron, fan-out) ─► calls back /api/inngest
   ▼                              ▼
 Supabase Auth            Supabase Postgres (+pgvector) · Storage
                                  ▲
 GitHub private vault ──sync──────┘  (notes → chunks → embeddings)

2. Components

  • Expo client: chat, canvas renderer, notes, agents, MCP store, approvals. Holds only the user session.
  • Next.js API: authenticates JWT, runs short chats, enqueues Inngest events, serves data endpoints.
  • Agent runtime: LangGraph graph per agent; Postgres checkpointer; tools = built-in + MCP.
  • Inngest functions: run graphs in durable steps, cron monitors, memory extraction, vault sync, canvas refresh.
  • Supabase: system of record for chats, runs, canvases, MCP config; index for notes.
  • Vault (GitHub): source of truth for notes.

3. Key flows

3.1 Short chat

  1. App POST /api/chat with messages + JWT.
  2. Server verifies user, loads memories + top-k notes, builds system prompt.
  3. streamText (or short graph piped via adapter) → UI message stream → useChat.
  4. On finish: persist messages; emit chat/completed to Inngest for memory extraction.

3.2 Long/background task

  1. Chat or button creates agent_runs row (queued) and sends agent/run.requested.
  2. Inngest function executes graph node-by-node in step.runs; each node writes run_events.
  3. App polls or subscribes (Supabase Realtime, verify) to run_events for a live timeline.
  4. Completion posts a result message and optionally a canvas.

3.3 Human approval

  1. Tool flagged requires_approval (or graph hits interrupt()).
  2. Run state → awaiting_approval; approvals row created; push notification optional.
  3. User taps Approve/Deny → POST /api/approvals/:id → Inngest event approval/decided.
  4. Function resumes graph with Command({ resume }); deny path lets the agent re-plan.
  5. Approvals expire after a timeout (default 24 h) and are treated as denied.

3.4 Memory

  • Short-term: thread messages + checkpointer state.
  • Long-term: after each conversation, Inngest asks the model to extract facts/preferences/decisions → dedupe against existing → upsert memories with embedding.
  • Retrieval: top-k memories (vector) injected into the system prompt each turn.

3.5 Notes / second brain

  1. Obsidian Git pushes vault to GitHub; webhook → /api/webhooks/github → Inngest vault/changed.
  2. Function fetches changed .md files, parses frontmatter + [[wikilinks]], chunks by heading, embeds, upserts notes, note_chunks, note_links.
  3. Agent tools search_notes, read_note, write_note (writes commit to the repo; write_note requires approval by default).

3.6 MCP store

  1. User taps Add on a server (mcp_servers registry).
  2. If OAuth/API key needed: flow completes at /api/mcp/oauth/callback; credentials encrypted (AES-256-GCM) → mcp_connections.
  3. User enables the server for an agent (agent_mcp_tools, with per-tool approval flags).
  4. At run start, server decrypts credentials server-side, connects, lists tools, filters by allow-list, adds to the graph.

3.7 Canvas

Agent calls render_canvas(spec) → zod-validated → saved in canvases → returned in the message as a tool part → Expo renders from the component catalog. Data-bound components reference a saved data source so refresh needs no LLM call.

3.8 Model routing

Every LLM call (chat route, graph nodes, memory extraction, canvas refresh) goes through getModel(id) / withFallback(ids). Registry entries declare capabilities and private_ok. Order of operations: capability check → call → on 429/5xx retry once → next fallback → log to provider_usage. Defaults: chat and agents on Google; cheap/fast steps (routing, summaries) may use Groq; OpenRouter is the long-tail and last-resort provider. Embeddings are pinned to one model.

4. Security model

  • Single allowed user; every API route verifies the Supabase JWT and ALLOWED_USER_ID. RLS on all tables as defense in depth.
  • Secrets only in Vercel env; MCP credentials encrypted at rest; decrypted only server-side at run time.
  • Prompt injection: treat all web content, files, and MCP tool descriptions/results as untrusted. Sensitive tools (send, delete, pay, write notes, push to repo) require approval by default. Never let tool output change the tool allow-list.
  • Canvas actions are a fixed enum; no eval, no model-supplied code. WebView HTML is sandboxed (no network, no native bridge).
  • Context derived from your notes/memories is sent only to models marked private_ok. Treat free tiers of any provider as possibly logged/trained on unless its terms say otherwise (verify).
  • Rate-limit endpoints; cap per-run steps and tokens to protect free quotas.

5. Failure handling

Retries with backoff (Inngest); model fallback on 429; run marked failed with error in run_events; idempotency keys on side-effecting tools; max-step guard in every graph.

DATABASE_SCHEMA.md

Database Schema (Supabase Postgres)

Keep the DB small (free cap 500 MB): files go to Storage, notes live in GitHub, DB holds metadata, chunks and embeddings. Vector dimension below assumes 768; set it to your embedding model's real dimension.

create extension if not exists vector;
create extension if not exists pgcrypto;

-- Conversations
create table threads (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id),
  agent_id uuid,
  title text,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
create table messages (
  id uuid primary key default gen_random_uuid(),
  thread_id uuid not null references threads(id) on delete cascade,
  user_id uuid not null,
  role text not null check (role in ('user','assistant','system','tool')),
  model text,                      -- registry id that produced it
  parts jsonb not null,            -- AI SDK UI message parts
  created_at timestamptz default now()
);
create index on messages (thread_id, created_at);

-- Memory
create table memories (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,
  kind text check (kind in ('fact','preference','decision','task')),
  content text not null,
  source_thread_id uuid,
  embedding vector(768),
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
create index on memories using hnsw (embedding vector_cosine_ops);

-- Second brain (index of the GitHub vault)
create table notes (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,
  path text not null,              -- e.g. "Projects/Idea.md"
  title text,
  frontmatter jsonb,
  content_hash text not null,
  git_sha text,
  updated_at timestamptz default now(),
  unique (user_id, path)
);
create table note_chunks (
  id uuid primary key default gen_random_uuid(),
  note_id uuid not null references notes(id) on delete cascade,
  idx int not null,
  heading text,
  content text not null,
  embedding vector(768),
  tsv tsvector generated always as (to_tsvector('english', content)) stored
);
create index on note_chunks using hnsw (embedding vector_cosine_ops);
create index on note_chunks using gin (tsv);
create table note_links (
  from_note uuid references notes(id) on delete cascade,
  to_path text not null,           -- target by path/title; may be unresolved
  primary key (from_note, to_path)
);

-- Uploaded documents (files in Storage)
create table documents (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,
  storage_path text not null,
  mime text, name text, size_bytes bigint,
  status text default 'uploaded' check (status in ('uploaded','processing','ready','failed')),
  created_at timestamptz default now()
);

-- Agents & MCP
create table agents (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,
  name text not null,
  role text,
  system_prompt text,
  model text default 'google:gemini-flash',   -- registry id "provider:modelId"
  fallback_models text[] default '{}',        -- ordered registry ids

  is_supervisor boolean default false,
  created_at timestamptz default now()
);
create table mcp_servers (            -- registry (global, seeded)
  id uuid primary key default gen_random_uuid(),
  slug text unique not null,
  name text not null,
  description text,
  url text not null,                   -- streamable HTTP endpoint
  auth_type text check (auth_type in ('none','api_key','oauth')),
  icon_url text,
  default_requires_approval boolean default true
);
create table mcp_connections (        -- per user credentials
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,
  server_id uuid not null references mcp_servers(id),
  credentials_enc bytea,               -- AES-256-GCM ciphertext (app-level)
  credentials_iv bytea,
  status text default 'active',
  created_at timestamptz default now(),
  unique (user_id, server_id)
);
create table agent_mcp_tools (
  id uuid primary key default gen_random_uuid(),
  agent_id uuid not null references agents(id) on delete cascade,
  connection_id uuid not null references mcp_connections(id) on delete cascade,
  tool_name text,                      -- null = all tools of the server

);
create unique index on agent_mcp_tools (agent_id, connection_id, coalesce(tool_name,''));

-- Runs, events, approvals
create table agent_runs (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,
  agent_id uuid, thread_id uuid,
  parent_run_id uuid references agent_runs(id),
  goal text not null,
  status text default 'queued' check (status in
    ('queued','running','awaiting_approval','succeeded','failed','cancelled')),

);
create table run_events (
  id bigint generated always as identity primary key,
  run_id uuid not null references agent_runs(id) on delete cascade,

  created_at timestamptz default now()

create index on run_events (run_id, id);
create table approvals (
  id uuid primary key default gen_random_uuid(),
  run_id uuid not null references agent_runs(id) on delete cascade,
  user_id uuid not null,
  tool_name text, args jsonb, reason text,
  status text default 'pending' check (status in ('pending','approved','denied','expired')),
  decided_at timestamptz, expires_at timestamptz
);

  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,

Search function (hybrid)

Expose an RPC search_notes(query_embedding, query_text, k) that combines cosine distance on note_chunks.embedding with ts_rank on tsv (reciprocal-rank fusion) and returns chunk, note path, heading, score.

LangGraph tables

Created by the checkpointer's setup() on the same database; don't hand-write them.

Row Level Security

Enable RLS on every table above. Policy pattern: using (user_id = auth.uid()); for child tables join through the parent. mcp_servers is read-only for authenticated users. Server code using the service role bypasses RLS, so always filter by user_id explicitly in server queries.

Retention (protect the 500 MB cap)

Prune run_events and provider_usage older than 30 days; keep agent_runs summaries. Truncate large tool outputs before storing. Store files only in Storage.

UI / UX Spec (Expo app)

1. Principles

  • Chat is home; everything else is one tap away.
  • Show work: long tasks show a live timeline, not a spinner.
  • Ask before acting: approvals are impossible to miss and fast to answer.
  • Native-feeling, dark and light themes, thumb-reachable controls.

2. Navigation (bottom tabs)

Tab Purpose
Chat Threads, composer, streaming messages, inline canvases
Canvas Saved dashboards/reports
Notes Vault browser, search, note view with backlinks
Agents Agent list, runs, MCP tools per agent
Store MCP server directory
Settings Profile, model, memory, vault, theme

Approvals badge appears on the tab bar and as a banner anywhere.

3. Screens

Chat: thread list drawer; composer with attach (image/PDF/file), mic (P2), agent picker, model picker (grouped by Google / Groq / OpenRouter, with capability badges and a warning if the model can't handle the attachment), mode toggle (Chat / Run as task). Messages render markdown, code with copy, citations as tappable chips, tool-call chips (collapsible), inline canvas cards, approval cards. Run detail: header (goal, status, elapsed), vertical timeline of events (node, tool call, result, retry), cancel button, final result. Child runs nest under the supervisor. Approval card: tool name, plain-language summary, arguments (expandable), buttons Approve / Deny, optional edit of arguments. States: pending, approved, denied, expired. Canvas list/detail: cards with title and last updated; detail renders spec full-screen, pull-to-refresh, "Ask about this" button that opens chat with the canvas as context. Notes: folder tree, search bar (hybrid), note view (markdown, [[links]] tappable, backlinks section), edit (writes need confirmation), "Ask agent about this note". Agents: list with role and MCP tool count; editor for name, role, instructions, primary model + fallback order, tools toggle list with per-tool "require approval". Store: grid of servers with icon, description, auth type. Tap Add → permission sheet listing tools → connect (OAuth in system browser or key entry) → enable for agents. Connected servers show a Manage state. Settings: sign out, memory viewer (list, delete), vault repo status and last sync, usage meter per provider (requests/tokens vs free limits), default model and fallback order, API key status (configured or missing, never shown), theme.

4. Canvas component catalog (v1)

Type Props Rendering notes
stat label, value, delta? Large number card
chart kind: line|bar|pie, data[{x,y}] Single series v1; touch tooltip
table columns, rows Horizontal scroll, sticky first column

Invalid or unknown nodes render a muted "can't display this block" card, never crash. Spec size limit 100 KB. Optional html fallback in sandboxed WebView (no network, no bridge).

5. Design tokens (starting point)

Spacing scale 4/8/12/16/24/32. Radius 8 (inputs), 12 (cards). Type: system font; sizes 12/14/16/20/28. Color roles: background, surface, text, text-muted, primary, success, warning, danger (define light and dark values). Minimum tap target 44 pt.

6. States & feedback

  • Loading: skeletons for lists; streaming cursor for chat.
  • Empty: say what to do next ("Add your vault in Settings to search notes").
  • Errors: plain cause + action ("Rate limit reached. Retrying in 20 s." / Retry button). No blame, no apology.
  • Offline: cached threads and canvases readable; composer queues until online.
  • Quota meter warns at 80% of monthly free limits.

7. Accessibility & platform

Dynamic type, screen reader labels on all controls and chart summaries (text alternative), reduced-motion respected, haptics on approvals. Primary target iOS/Android via Expo; web build is optional later.

8. Voice (P2)

Hold-to-talk using device speech recognition, transcript editable before sending; read-aloud toggle per message using device TTS.

IMPLEMENTATION_PLAN.md

Implementation Plan

Build vertical slices. Each phase ends in something you can use. Estimates assume solo, part-time.

Phase 0: Setup (1–2 days)

  • [ ] Monorepo (apps/api Next.js, apps/mobile Expo, packages/shared zod schemas)
  • [ ] Supabase project, GitHub OAuth, allow-list your account
  • [ ] Vercel deploy, env vars, Inngest app connected
  • [ ] GitHub Actions cron keepalive for Supabase
  • [ ] Install providers: @ai-sdk/google, @ai-sdk/groq, @openrouter/ai-sdk-provider; add the 3 API keys to Vercel env Done when: signed-in Expo app calls a protected /api/health.

Phase 0.5: LLM provider layer (1–2 days)

All model access goes through one module, packages/shared/models.ts. No route, graph node or Inngest function may import a provider package directly. - [ ] Model registry (code, typed). One entry per model: id ("google:gemini-flash"), provider, providerModelId, label, capability flags { tools, vision, structuredOutput, reasoning, pdf }, contextWindow, private_ok (safe for note-derived context), tier (free/paid). - [ ] Resolver getModel(id) → AI SDK LanguageModel using the matching provider instance (google, createGroq, createOpenRouter). Unknown id or missing API key → typed error. - [ ] Fallback chain withFallback([primary, ...fallbacks]): on 429, 5xx, timeout or provider error, retry once with backoff, then move to the next model. Skip fallbacks lacking a capability the request needs (e.g. images → needs vision, tool-using agent → needs tools). - [ ] Capability gate: reject or reroute before calling if the request needs something the chosen model lacks. - [ ] Usage tracking: write each call to provider_usage (provider, model, tokens, status); expose to the usage meter. - [ ] Embeddings stay on one fixed provider/model (Google by default, verify) regardless of chat model, so vectors remain comparable. Changing embedding model means re-embedding everything. - [ ] /api/models returns registry + which providers have keys + today's usage. Done when: the same prompt runs on Google, Groq and OpenRouter by changing only the model id, and a forced 429 on the primary falls through to the next model.

Sketch:

import { google } from "@ai-sdk/google";
import { createGroq } from "@ai-sdk/groq";
import { createOpenRouter } from "@openrouter/ai-sdk-provider";

const groq = createGroq({ apiKey: process.env.GROQ_API_KEY });
const openrouter = createOpenRouter({ apiKey: process.env.OPENROUTER_API_KEY });

export function getModel(id: string) {
  const [provider, ...rest] = id.split(":"); const m = rest.join(":");
  switch (provider) {
    case "google": return google(m);
    case "groq": return groq(m);
    case "openrouter": return openrouter.chat(m);
    default: throw new Error(`Unknown provider: ${provider}`);
  }
}

Model ids in the registry are placeholders: pick current ids from each provider's docs at build time, since model lineups and free tiers change often.

Phase 1: Chat (3–5 days)

  • [ ] GitHub vault sync → chunks → embeddings → hybrid search RPC
  • [ ] search_notes, read_note; notes screen with backlinks
  • [ ] Inngest chat/completed memory extraction; memory viewer Done when: agent cites an old note and recalls a stated preference in a new thread.

  • [ ] LangGraph single agent (plan → act → observe), Postgres checkpointer, max-step guard
  • [ ] Graph nodes obtain models only via getModel()/withFallback; per-node model choice (e.g. fast Groq model for routing/summaries, stronger model for final answer)
  • [ ] Run via Inngest durable steps; agent_runs/run_events; timeline UI
  • [ ] Retry/self-correction node Done when: a 5-minute research task runs after closing the app and posts its result.

Phase 4: Approvals (2–3 days)

  • [ ] interrupt() + approvals + approval card + approval/decided resume
  • [ ] write_note and other sensitive tools gated Done when: deny re-plans, approve proceeds, expiry works.

Phase 5: Canvas (4–6 days)

  • [ ] Shared Canvas zod schema, renderer for core components, fixtures first
  • [ ] render_canvas / update_canvas, canvases table, Canvas tab
  • [ ] Data sources + pull-to-refresh + Inngest scheduled refresh Done when: "make a dashboard of X" yields a native, refreshable canvas.

Phase 6: MCP store (4–6 days)

  • [ ] Seed registry (hand-pick 5–10 remote servers)
  • [ ] Connect flows (none / API key / OAuth), encrypted credentials
  • [ ] Per-agent tool enablement, approval flags, runtime tool loading Done when: add a server in ≤ 3 taps and use its tool in the next run.

Phase 7: Multi-agent (5–7 days)

  • [ ] Agent CRUD (each agent has primary model + fallbacks); supervisor graph; specialist subgraphs
  • [ ] Cross-check pattern: verifier runs on a different provider than the worker
  • [ ] Parallel research fan-out, verifier node, nested timeline Done when: supervisor delegates to 2+ agents and merges cross-checked results.

Phase 8: Extras (as wanted)

Website monitors → image generation (verify free) → voice (device APIs) → code sandbox → X data (paid).

Testing

  • Unit: zod schemas, chunker, wikilink parser, encryption round-trip, model resolver, fallback ordering, capability gate.
  • Provider contract tests: one tool-call prompt, one structured-output prompt, one image prompt per registry model (run manually, they consume quota).
  • Integration: graph with mocked LLM/tools, approval resume, vault sync on a fixture repo.
  • Security: prompt-injection fixtures (malicious page/tool result must not trigger tools); RLS tests with a second user.
  • Manual: real-device streaming, airplane-mode behavior.

Risks

Risk Mitigation
Free quotas change/exhaust Usage meter, step/token caps, cross-provider fallback, re-verify limits quarterly
Models differ in tool-calling, vision and structured-output reliability Capability flags + contract tests; don't assume a model supports a feature
Free/community models may log or train on prompts (check each provider's terms) private_ok flag; note-derived context only goes to private_ok models
OpenRouter provider is community-maintained Pin version; isolated behind getModel() so it can be swapped
Provider package/API changes Single integration module, version pins
Supabase pause Keepalive cron, runbook to unpause
Gemini privacy on free tier Don't send private notes by default; add a per-agent "private" model setting
Streaming issues on device XHR transport fallback
Prompt injection via MCP/web Approval defaults, untrusted-content handling, allow-lists
Scope creep Ship phases in order; each has a done-when

Definition of done (v1)

Phases 0–6 (including 0.5) complete, with Google, Groq and OpenRouter selectable and falling back automatically, running on Vercel + Supabase + Inngest free tiers, installed on your phone, with usage meter and backups of the vault in GitHub.
